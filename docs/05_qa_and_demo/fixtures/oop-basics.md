# Object-Oriented Programming Fundamentals

Object-Oriented Programming (OOP) is a programming paradigm based on the concept of "objects", which can contain data and code: data in the form of fields (often known as attributes or properties), and code in the form of procedures (often known as methods).

## Four Core Pillars

1. **Encapsulation**: Bundling data and methods that operate on that data within a single unit, while restricting direct access to internal state using private fields and public accessors.
2. **Abstraction**: Hiding complex implementation details and exposing only the essential interface to the user.
3. **Inheritance**: A mechanism where a new class derives properties and characteristics from an existing base class.
4. **Polymorphism**: The ability of different classes to respond to the same method call in ways specific to their own data type.

## Design Principles: SOLID

- **Single Responsibility Principle (SRP)**: A class should have only one reason to change.
- **Open/Closed Principle (OCP)**: Software entities should be open for extension, but closed for modification.
- **Liskov Substitution Principle (LSP)**: Subtypes must be substitutable for their base types without altering program correctness.
- **Interface Segregation Principle (ISP)**: Clients should not be forced to depend upon interfaces they do not use.
- **Dependency Inversion Principle (DIP)**: Depend upon abstractions, not concrete implementations.
